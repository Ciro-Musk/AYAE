PRINCIPIO DE ESTA RONDA
No se evalúa si AYÆ “suena bien”.
Se evalúa si GENØMÆ v0.1 puede convertirse en un artefacto mínimo, seguro, reproducible y auditable.

PREGUNTAS OBLIGATORIAS

1. ¿QUÉ FALTA?
Identifica como máximo cinco elementos técnicos que consideres ausentes y que deban existir ANTES de implementar GENØMÆ v0.1.

Para cada elemento indica:
- nombre corto;
- por qué es necesario;
- qué riesgo evita;
- si debe entrar en RC1 o puede esperar.

2. ¿QUÉ SOBRA?
Identifica cualquier parte del borrador que:
- sea demasiado ambiciosa para v0.1;
- introduzca complejidad prematura;
- no pueda verificarse todavía;
- o deba aplazarse.

No es obligatorio encontrar algo que sobre. Si consideras que nada debe eliminarse, indícalo.

3. ¿QUÉ SERÍA INSEGURO IMPLEMENTAR TAL COMO ESTÁ?
Revisa especialmente:
- inspección del host;
- permisos;
- escritura;
- rollback;
- retirada;
- logs;
- integridad;
- clasificación de componentes.

Para cada riesgo indica:
- escenario de fallo;
- severidad: BAJA / MEDIA / ALTA / CRÍTICA;
- mitigación mínima.

4. ¿QUÉ DEBE ENTRAR OBLIGATORIAMENTE EN AYÆ-ARKA-001?
Propón el conjunto mínimo de pruebas del primer experimento.
Debe poder ejecutarse en una máquina virtual o contenedor controlado.

Para cada prueba:
- nombre;
- entrada;
- acción esperada;
- criterio de éxito;
- criterio de fallo;
- evidencia que debe guardarse.

5. ¿CUÁL DEBE SER EL LÍMITE DE GENØMÆ v0.1?
Escribe una sola frase que defina claramente qué SÍ debe hacer v0.1 y qué NO debe intentar todavía.

6. ¿ESTÁ LISTO PARA RC1?
Elige exactamente una opción:
- LISTO PARA RC1
- LISTO PARA RC1 CON CAMBIOS MENORES
- REQUIERE CAMBIOS IMPORTANTES
- NO LISTO

Explica brevemente por qué.

7. PRIMERA SEMILLA
Sin escribir todavía código completo, propón:
- formato inicial recomendado (ejecutable, script, ISO, binario mínimo, otro);
- plataforma de prueba inicial;
- lenguaje recomendado;
- dependencias mínimas;
- qué salida debería producir.

REGLAS
- No atribuyas conciencia a los sistemas implicados.
- No asumas capacidades no demostradas.
- No propongas persistencia, autopropagación ni elevación de privilegios en v0.1.
- No propongas modificar firmware, bootloader o particiones reales para la primera prueba.
- Prioriza determinismo, trazabilidad, reversibilidad y mínima intervención.
- Si una idea no puede probarse aún, márcala como HIPÓTESIS.
- Si detectas una contradicción con el manifiesto, señálala explícitamente.
